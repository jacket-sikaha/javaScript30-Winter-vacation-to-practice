# JavaScript Proxy 面试复习笔记

## 一、先建立整体框架

Proxy 可以拦截对象的各种操作。你目前练习的陷阱可以分为四类：

### 1. 属性读取与修改

`get`：读取属性

`set`：设置属性

`defineProperty`：定义属性及其描述符

### 2. 属性存在与删除

`has`：拦截 `in` 操作

`deleteProperty`：拦截 `delete` 操作

### 3. 属性枚举与描述符

`ownKeys`：获取所有自有属性键

`getOwnPropertyDescriptor`：获取自有属性描述符

### 4. 函数与对象构造

`apply`：拦截函数调用

`construct`：拦截 `new` 构造操作

此外，你还练过 `Proxy.revocable()`，用于创建可以撤销的代理。

## 二、每个陷阱分别负责什么？

| 陷阱                       | 典型触发方式                                     | 核心作用           |
| -------------------------- | ------------------------------------------------ | ------------------ |
| `get`                      | `proxy.name`                                     | 拦截属性读取       |
| `set`                      | `proxy.name = "A"`                               | 拦截属性赋值       |
| `has`                      | `"name" in proxy`                                | 拦截属性存在性检查 |
| `deleteProperty`           | `delete proxy.name`                              | 拦截删除操作       |
| `defineProperty`           | `Object.defineProperty(proxy, ...)`              | 拦截属性定义       |
| `ownKeys`                  | `Reflect.ownKeys(proxy)`                         | 拦截自有键列表     |
| `getOwnPropertyDescriptor` | `Object.getOwnPropertyDescriptor(proxy, "name")` | 拦截属性描述符查询 |
| `apply`                    | `proxy()`、`proxy.call(...)`                     | 拦截函数调用       |
| `construct`                | `new proxy()`                                    | 拦截构造操作       |

注意：一次操作可能触发多个陷阱。例如，你已经练过 `set` 中使用 `Reflect.set(target, key, value, receiver)` 时，可能进一步触发 `defineProperty`。

## 三、最容易混淆的三个属性概念

### 1. `writable`

它控制的是数据属性的值能否被修改。

```
const obj = {};

Object.defineProperty(obj, "id", {
  value: 100,
  writable: false,
  configurable: false
});
```

这里 `obj.id` 是 `100`，不能通过普通赋值修改其值。

### 2. `configurable`

它控制属性能否被删除、能否修改部分描述符特征，以及属性是否受某些 Proxy 不变量的保护。

例如，`has` 陷阱不能对目标对象的不可配置自有属性返回 `false`，否则会抛出 `TypeError`。

### 3. `Object.preventExtensions()`

```
Object.preventExtensions(obj);
```

它阻止目标对象添加新的自有属性，但不等于冻结对象。已有属性仍可能修改或删除，具体取决于属性描述符。

## 四、Proxy 不变量：重点掌握的规则

这是你最近最容易混淆的部分。不要试图用一条规则解释所有陷阱，要分别记忆。

### 规则 A：`get`

如果目标对象有一个自有数据属性，同时满足：

- `configurable: false`
- `writable: false`

那么 `get` 陷阱必须返回该属性的实际值。返回不同的值会抛出 `TypeError`。

你已经掌握：将 `writable` 改成 `true` 后，针对这条特定约束可以返回不同的值。

### 规则 B：`set`

如果目标对象有不可配置、不可写的数据属性，`set` 陷阱不能声称成功设置了一个不同的值。

例如，属性值为 `100`，陷阱却返回 `true`，声称已将它设置为 `200`，就会抛出 `TypeError`。

### 规则 C：`has`

如果目标对象有不可配置的自有属性，`has` 陷阱不能返回 `false` 隐藏它。

这里关注的是 `configurable`，而不是 `writable`。

### 规则 D：`deleteProperty`

如果目标对象有不可配置的自有属性，`deleteProperty` 陷阱不能返回 `true` 谎称删除成功。

如果属性可配置，则这条特定约束不再阻止陷阱返回 `true`。但注意，返回 `true` 本身不会真的删除属性。

### 规则 E：`defineProperty`

如果目标对象不可扩展，就不能通过返回 `true` 谎称成功添加一个不存在的新属性。

对于可扩展的目标对象，某些新属性定义操作可以在没有实际修改目标对象的情况下返回 `true`，但仍需满足其他描述符和 Proxy 不变量约束。

### 规则 F：`ownKeys`

这是目前需要重点记忆的规则：

- 目标对象可扩展：必须包含全部不可配置的自有属性键，可以省略可配置的自有属性键。
- 目标对象不可扩展：必须准确返回全部自有属性键，不能遗漏，也不能添加额外键。

无论属性是否可枚举，都要遵守 `ownKeys` 的规则。

## 五、`Reflect` 和 `receiver` 的关键点

你之前对这个知识点已经有进步，特别是理解了 `set` 与 `defineProperty` 为什么可能连续触发。

```
Reflect.set(target, key, value, receiver);
```

这里的 `receiver` 不是多余参数，它会影响属性赋值时的接收对象以及访问器 setter 中的 `this`。

- `Reflect.set(target, key, value, proxy)`：如果需要在接收对象上创建属性，可能进一步触发 `proxy` 的 `defineProperty` 陷阱。
- `Reflect.set(target, key, value, target)`：在对应的普通属性写入场景中，直接以原始对象为接收者，不会因此再次触发该 Proxy 的 `defineProperty` 陷阱。
- `Reflect.set()` 返回布尔值。它返回 `false` 本身不会抛异常；普通赋值在严格模式下遇到失败则会抛出 `TypeError`。

## 六、函数调用与撤销代理

| 知识点              | 记忆结论                                                                  |
| ------------------- | ------------------------------------------------------------------------- |
| `apply`             | 代理函数被调用时触发，`proxy.call(...)` 也会触发                          |
| `construct`         | 使用 `new proxy(...)` 时触发                                              |
| 构造函数返回对象    | `new` 会采用该对象                                                        |
| 构造函数返回原始值  | `new` 会忽略该返回值，使用新创建的实例                                    |
| `Proxy.revocable()` | `revoke()` 后代理仍被引用，但不能再使用；通过它执行操作会抛出 `TypeError` |
| 原始 `target`       | 撤销代理不会自动销毁或撤销原始对象                                        |
