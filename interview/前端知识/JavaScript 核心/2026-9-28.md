Promise.resolve() 如果接收到一个 Promise，会直接返回/采用它的状态；如果接收到 thenable，则会读取并调用它的 then 方法，根据其 resolve/reject 调用结果来确定返回 Promise 的状态和值。

Promise.resolve(普通值)
→ 创建 fulfilled Promise

Promise.resolve(Promise)
→ 直接返回这个 Promise

Promise.resolve(thenable)
→ 采用 thenable 的状态/结果

---

.then() 回调中 return 一个 Promise 时，外层 Promise 会等待这个 Promise settle，并采用它的最终状态和值。

---

所以可以把 Promise 链简单理解成：
return 普通值
↓
fulfilled
↓
继续执行 then

throw 异常
↓
rejected
↓
跳过后续 then，寻找 catch

---

可以记成：
finally 正常结束
↓
保留原 Promise 的状态和值

finally 抛异常 / 返回 rejected Promise
↓
变成 rejected

这题你主要需要修正一点：finally 不是普通的 then，它的正常 return 不会把值传给下一个 then

---

一个很重要的面试表格
finally 发生什么 后续结果
正常结束 / return 100 保留原状态和值
throw new Error() 变成 rejected(Error)
return Promise.reject(...) 变成 rejected(...)
return Promise.resolve(100) 仍然保留原状态和值

所以你现在可以把 finally 理解成：
“无论成功失败都执行的清理逻辑；正常情况下不改变 Promise 结果。”

---

async 函数中，await 之前的代码同步执行；await 之后的代码会在后续微任务中继续执行。

---

async function foo() {
return Promise.resolve(1);
}

async function bar() {
return await Promise.resolve(2);
}

最终值/状态通常相同，但 return await 多了一个 await 的异步恢复过程。

---

在没有 try/catch 的情况下，最终通常都会让 async 函数返回 rejected Promise。
但是放进：
try {
...
} catch {}

里面时：
return Promise.reject()
↓
不会被当前 try/catch 捕获

return await Promise.reject()
↓
await 把 rejection 转成异常
↓
可以被当前 try/catch 捕获
