为什么没有 props / Context 也会 render？

这就是这道题最重要的知识点。

你可以记住：

父组件重新 render，默认会导致它下面的普通子组件也参与 render/reconciliation，即使子组件的 props 没变化。

---

React.memo 主要解决的是父组件 render 导致的 props 没变化子组件跟着 render；
但如果子组件自己通过 useContext 订阅了 Context，Context value 发生变化，React.memo 也挡不住。

---

一个组件 render 的原因可能很多：

组件 render
├── 自己的 state 更新
├── 父组件 render
├── props 变化
├── Context value 变化
└── 其他 React 更新机制

---

React.memo
│
├── 父组件 render
│ ↓
│ props 没变 → 可以跳过
│
├── 父组件 render
│ ↓
│ props 变了 → render
│
├── 自己 state 变了 → render
│
└── useContext 的 value 变了 → render

## 两种对比策略

### ❌ 如果不用 key / 用 index 当下标（按位置匹配）

React Diff 逻辑：拿**新数组第 0 个**对比旧数组**第 0 个**，新数组第 1 个对比旧数组第 1 个

1. 旧 0：`<User key="a">` vs 新 0：`<User key="b">` → 不一样，销毁 a，新建 b
2. 旧 1：`<User key="b">` vs 新 1：`<User key="a">` → 不一样，销毁 b，新建 a

**后果：DOM 全部销毁重建，组件 state、内部状态全部丢失，触发完整卸载 + 挂载，性能差。**

### ✅ 有正确 key 的时候（按 key 身份匹配，不是按位置）

Diff 流程：

1. 先把旧节点做成一张映射表：`{ a:旧a节点, b:旧b节点 }`
2. 遍历新数组，拿**新的 key**去旧映射表里找有没有一模一样 key 的旧节点

- 新第一个 key=`b`：旧里面找到 key=b 的老节点 → **复用这个 DOM，只移动 DOM 位置，不销毁重建**
- 新第二个 key=`a`：旧里面找到 key=a 的老节点 → **复用 DOM，移动位置**

> 重点：**不管现在排在第几位，只要 key 相同，就复用原来那个组件 / DOM，保留组件内部 state，只做 DOM 移动操作**。
> React 不会认为 “现在排在第一位就要复用以前第一位的 DOM”。
