② key 是不是为了让 Diff 更快？

🟡 不能简单这么说。

这是面试里很容易踩的坑。

key 确实有助于 React 在列表 reconciliation 时判断哪些元素是相同身份、哪些发生了新增/删除/移动，因此可以更合理地复用现有节点。

但核心不是：

“为了提高 Diff 算法速度。”

而是：

为了正确识别列表元素的身份，从而正确进行 reconciliation 和复用。

性能是结果之一，identity 才是核心。

---

React 为什么需要 key？

你可以直接回答：

key 的核心作用是帮助 React 在多次 Render 之间识别列表元素的稳定身份，从而在 reconciliation 时正确判断哪些元素可以复用、哪些新增、删除或者移动。

---

使用 index 作为 key 的问题在于，当列表发生插入、删除或排序时，index 会发生变化，可能导致 React 复用错误的组件实例，从而出现 state 错位等问题。

---

“Context 导致很多组件 Render，你怎么定位和优化？”

你可以这么答：

首先使用 React DevTools Profiler 确认具体是哪些组件发生了不必要的 Render，然后检查 Context Provider 的 value 是否在每次父组件 Render 时产生了新的引用。如果是，可以使用 useMemo 稳定 value。其次根据状态的更新频率和业务职责拆分 Context，避免一个 Context 承载大量互不相关的状态。对于大型状态场景，还可以缩小 Context Consumer 的范围，或者使用 Zustand 等支持 selector 的状态管理方案，减少无关组件的更新。

---

Hooks 不允许放在条件、循环和嵌套函数中，本质是为了保证每次 render 的 Hook 调用顺序稳定，从而让 React 能正确关联每个 Hook 对应的状态。

什么时候需要受控？

当你需要让 React 实时知道并控制这个值：

实时校验
实时格式化
根据输入动态显示 UI
控制按钮 disabled
条件渲染
多个组件共享表单值
提交前统一处理

---

“50 个字段全部受控，一定有性能问题吗？”

最佳回答是：

不一定。关键看 state 更新导致的组件 render 范围和每次 render 的成本。如果表单组件很大、字段更新频繁，可以通过组件拆分、React.memo、局部状态或者字段级订阅来降低不必要的渲染。

---

React 对 state 更新会进行引用/值比较；如果设置的是相同的对象引用，React 通常可以直接跳过这次更新。

---

为什么 React 推荐不可变更新？

核心有三个：

1. 方便 React 判断数据有没有变化
   oldUser !== newUser

React 可以快速通过引用判断：

“这个 state 对象是不是换了？”

3. 对性能优化非常重要

你前面刚学过：

React.memo
useMemo
Context

它们大量依赖引用是否稳定。

例如：

oldUser === newUser

可以帮助 React 判断：

这个对象没变化，可以复用。
